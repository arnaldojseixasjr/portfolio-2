// 01 — arsenal_deploy

Onde Subir Projetos de Graça

"Sem link de deploy = projeto morto aos olhos do recrutador." Esta frase da Parte 1 não é retórica — é a regra que separa perfis aprovados dos reprovados. As 6 plataformas abaixo cobrem todos os cenários, do site estático à API back-end, e todas têm plano gratuito generoso. Escolha pela stack, não pela marca.

GitHub Pages

Hospedagem estática nativa do GitHub

100% Grátis

A opção mais simples para sites estáticos: HTML/CSS/JS puro, documentação, portfolios, ou builds de projetos React/Vite (depois do npm run build). Já está dentro do GitHub — sem nova conta, sem nova fatura. O limite é 100GB de banda/mês, mais que suficiente para um portfólio.

Atalho em 3 cliques

  1. 1. Abra o repositório → vá em Settings
  2. 2. No menu lateral → clique em Pages
  3. 3. Em Source escolha Branch: main → Save

Em ~1 minuto seu site estará em https://usuario.github.io/repositorio/

Use para

Portfólio, currículo online, docs, projetos vanilla JS, builds estáticos

Evite para

APIs, banco de dados, server-side rendering, lógica de back-end

Abrir pages.github.com

Builds de React no GitHub Pages

O caminho quando você não quer Vercel

Dá para rodar React, Vue ou Svelte no GitHub Pages, mas precisa de 2 cuidados extras que iniciantes esquecem — e que custam horas de "por que minha tela está em branco?":

1. Configurar o base no Vite

O GitHub Pages serve em /repositorio/, não na raiz. Em vite.config.js: 

export default defineConfig({
  base: '/meu-repo/',
  plugins: [react()]
})

2. Adicionar gh-pages e script de deploy

npm i -D gh-pages
// package.json
"scripts": {
  "deploy": "npm run build &&
    gh-pages -d dist"
}

Para projetos estáticos sem framework, pule direto para Settings → Pages. Vai direto.

Vercel

A casa do Next.js — mas roda qualquer front

Hobby Grátis

Criada pela equipe do Next.js, é a referência para projetos React/Vue/Svelte com SSR, API routes ou funções serverless. Detecta o framework automaticamente, faz preview-deploy a cada PR e tem CDN global gratuita. O plano Hobby cobre portfólios e MVPs sem cobrar — basta não usar para fins comerciais de alto tráfego.

Conexão em 2 cliques

  1. 1. Clique em "Add New → Project" e autorize o GitHub
  2. 2. Selecione o repositório → clique em Deploy

A partir daqui, todo git push re-deploya automaticamente.

Use para

Next.js, React, Vue, Svelte, Astro, sites Tailwind, MVPs com API routes

Evite para

Back-ends pesados, long-running tasks, WebSockets persistentes, Docker custom

Abrir vercel.com

Netlify

A alternativa mais "drag-and-drop" do mercado

Starter Grátis

Faz exatamente o que a Vercel faz para front-end e estáticos — com a vantagem de aceitar arrastar-soltar uma pasta direto no painel (sem nem precisar de repositório) e ter funções serverless em JavaScript puro. Perfeita para quem está começando e quer ver algo no ar em 30 segundos.

Conexão em 2 cliques

  1. 1. Clique em "Add new site → Import an existing project"
  2. 2. Escolha o repositório no GitHub → Deploy site

Sem repo? Arraste a pasta dist/ direto em app.netlify.com/drop

Use para

Sites estáticos, SPAs, formulários integrados, deploy de pasta, MVPs sem back

Evite para

Apps que precisam de SSR pesado, banco relacional, runtime de longa duração

Abrir netlify.com

Render

O "Heroku da nova geração"

Free

Suporta Node.js, Python, Ruby, Go, Rust, Docker — o mais flexível dos três. Tem instâncias web, workers em background, banco PostgreSQL e Redis no plano grátis. O único porém: o free tier "adormece" após 15 min de inatividade e demora ~50s para "acordar" na próxima request.

Ponto de atenção

Cold-start de ~50s no free. Para MVP de portfólio é tranquilo — para produção comercial, considera plano pago.

Abrir render.com

Railway

UX premium, deploy com 1 clique

Trial + Hobby

O mais fácil para subir APIs Node/Python/Go: detecção automática de framework, banco PostgreSQL/Redis "de branca" e painel lindíssimo. Não tem free ilimitado de verdade — mas oferece crédito mensal de US$5 que cobre MVPs de baixo tráfego. Para a aula é mais que suficiente.

Destaque

Adiciona PostgreSQL com 1 clique. Detecção de package.json automática. Logs em tempo real.

Abrir railway.app

Koyeb

Free generoso, Docker-native

Free

Aposta para quem precisa de Docker custom no free tier. Aceita deploy de Dockerfile direto do GitHub, com auto-deploy por PR e endpoints globais. O free tier oferece 1 serviço web + 1 worker sem cold-start tão agressivo quanto o Render.

Destaque

Suporta Docker sem precisar de plano pago. SSL automático. Sem cold-start na mesma medida do Render.

Abrir koyeb.com

Comparativo rápido — qual escolher?

Cenário Plataforma Por quê
Currículo HTML puro, portfólio vanilla JS GitHub Pages Já está no GitHub, sem conta nova.
React/Next.js com API routes Vercel Integração nativa, CDN global, preview por PR.
Site estático sem repo (deploy de pasta) Netlify Drop Arrasta-solta a pasta dist/ e pronto.
API Node/Express com banco Render Free ilimitado + PostgreSQL grátis. Tem cold-start.
API com banco em 5 minutos Railway UX premium, mas atente ao crédito mensal.
API em Docker custom Koyeb Free com suporte a Dockerfile direto.

// 02 — engenharia_de_prompts

IA como Co-piloto de Personal Branding

ChatGPT, Claude e Gemini não vão escrever sua marca por você — mas vão acelerar 10× a primeira versão de qualquer texto profissional. Os 4 prompts abaixo foram calibrados como "atores especializados": cada um assume um papel (recrutador, especialista em DevRel, copywriter de LinkedIn) e segue uma estrutura com entregável claro. Copie, preencha os [colchetes] e rode.

Princípio da oficina: a IA é co-piloto, não piloto.

Use a IA para a primeira versão. Depois, reescreva 30% com a sua voz. Recrutadores e líderes técnicos reconhecem texto "cru de LLM" a quilômetros de distância — e isso desvaloriza o perfil. A regra de ouro: se a IA escreveu, você revisa.

01

Para: ChatGPT / Claude

README.md Impactante para Projetos no GitHub

DevRel

Gera um README profissional seguindo as 5 seções que recrutadores procuram, com badges Shields.io prontos. Preencha os dados do projeto nos colchetes.

prompt.txt 
Atue como um Tech Recruiter e Especialista em Developer Relations. Escreva um arquivo README.md profissional em Markdown para o meu projeto no GitHub.

Dados do Projeto:
- Nome do Projeto: [Insira o Nome]
- O que ele faz: [Descreva o projeto em 2 frases]
- Tecnologias Usadas: [ex: React, Node.js, Tailwind CSS]
- Principais Funcionalidades: [Liste 3 ou 4 recursos]
- Link do Projeto Online: [Cole o link da Vercel/GitHub Pages se houver]

Requisitos do README:
1. Título impactante com badge de status do projeto.
2. Seção "Sobre o Projeto" explicando o problema e a solução.
3. Tabela ou lista visual de tecnologias (com badges do shields.io).
4. Como executar o projeto localmente (passo a passo com git clone, npm install, etc.).
5. Seção de contato com links para meu LinkedIn e E-mail.
02

Para: ChatGPT / Claude

Profile README — Apresentação Pessoal no GitHub

Branding

Gera o conteúdo do repositório especial username/username — a página que aparece no topo do perfil do GitHub, com sua bio, stack e links.

prompt.txt 
Atue como um Especialista em Personal Branding para Desenvolvedores. Escreva o conteúdo de um arquivo README.md para o meu repositório especial "username/username" (Profile README do GitHub) — aquele que aparece automaticamente no topo do meu perfil público.

Dados sobre mim:
- Nome: [Seu Nome Completo]
- Cargo atual / área: [ex: Desenvolvedor Front-end Júnior]
- Stack dominada: [ex: React, TypeScript, Tailwind, Node.js]
- Tempo de experiência: [ex: 1 ano / estudante do 3º semestre]
- Foco / interesse atual: [ex: Acessibilidade web, performance, design systems]
- Projetos que mais orgulho: [listar 2 ou 3]
- Onde me encontrar: [LinkedIn, e-mail, portfólio]

Requisitos do Profile README:
1. Cabeçalho com apresentação em 1-2 frases (sem clichês, sem "apaixonado por tecnologia").
2. Linha de badges Shields.io com minha stack.
3. Seção "Atualmente aprendendo" ou "Foco atual".
4. Seção "Projetos em destaque" — 2 ou 3 cards resumidos.
5. Seção "Vamos conversar?" com ícones e links de contato.
6. Use emojis com parcimônia (máximo 1 por linha) e mantenha tom profissional e humano.
03

Para: ChatGPT / Claude

Headline Estratégico para o LinkedIn

SEO LinkedIn

Gera 10 variações de headline seguindo a fórmula "stack + solução que entrega". Você escolhe a melhor — e a IA justifica por quê.

prompt.txt 
Atue como um Copywriter especializado em LinkedIn para profissionais de tecnologia. Gere 10 variações de headline (até 220 caracteres cada) para o meu perfil do LinkedIn.

Dados:
- Cargo / área: [ex: Desenvolvedora Front-end]
- Stack principal: [ex: React, TypeScript, Tailwind]
- Setor ou domínio: [ex: Fintech, E-commerce, Educação]
- Solução que entrego: [ex: interfaces acessíveis que aumentam conversão]
- Senioridade: [ex: Júnior / Pleno / Sênior]

Regras das 10 variações:
1. NÃO usar "Buscando recolocação", "Disponível no mercado", "Apaixonado por tecnologia" ou emojis genéricos.
2. Cada variação deve seguir uma destas fórmulas:
   - "Cargo | Stack | Solução que entrega"
   - "Stack + resultado mensurável para o negócio"
   - "Cargo focado em [domínio] | Stack | diferencial"
3. Para cada variação, escreva ao lado, em itálico, por que ela funciona (palavras-chave de busca, clareza, posicionamento).
4. No final, indique a variação com melhor equilíbrio entre SEO, autoridade e humanidade, e sugira 1 ajuste fino.
04

Para: ChatGPT / Claude

Narrativa do "Sobre" no LinkedIn

Storytelling

Escreve a seção "Sobre" do LinkedIn em formato de história humana: por que entrou em tech, o que constrói hoje, para onde vai. Tono próximo, sem jargão.

prompt.txt 
Atue como um Storyteller profissional especializado em narrativas de carreira para desenvolvedores. Escreva a seção "Sobre" do meu LinkedIn (entre 180 e 260 palavras), em primeira pessoa, em tom humano e conversacional — como se eu estivesse explicando minha trajetória para um colega de turma que acabou de conhecer.

Dados para a narrativa:
- Por que entrei na tecnologia: [sua história real — ex: "comecei montando sites pra banda de amigos"]
- Stack dominada hoje: [ex: React + TypeScript]
- Projeto do qual mais orgulho: [cite 1 e explique por quê em 1 frase]
- O que mais me empolga resolver: [ex: acessibilidade, performance, DX]
- Para onde quero ir: [ex: virar referência em a11y front-end]

Regras:
1. Abra com uma frase-gancho que NÃO comece com "Sou desenvolvedor..." — comece com uma cena, imagem ou virada.
2. Evite jargão corporativo ("sinergia", "ecossistema", "disruptivo").
3. Estruture em 3 parágrafos curtos: origem → hoje → futuro.
4. Termine com 1 convite explícito (ex: "se você também se preocupa com acessibilidade, vamos conversar").
5. Não use mais de 2 emojis em todo o texto.

Fluxo recomendado durante a oficina

Rode o Prompt 01 ao atualizar o README de cada repositório. Rode o Prompt 02 ao montar seu Profile README do GitHub. Rode o Prompt 03 e o Prompt 04 ao ajustar o LinkedIn. Sempre revise e personalize ao menos 30% antes de publicar — marca pessoal não se delega.

// 03 — oficina_pratica

Operação Profile Up

~90 min

Chegou a hora de colocar o mouse na mão. Em 7 etapas, cada aluno sai da aula com: foto e username atualizados, Profile README no ar, 6 repositórios fixados, 1 README de projeto profissional, 1 deploy público, headline e "Sobre" do LinkedIn reescritos, e o rascunho do primeiro post da série "1 projeto = 5 posts". Marque cada etapa conforme avança — a barra no final acompanha seu progresso.

Auditar seu perfil atual

~10 min Diagnóstico

Antes de mexer em qualquer coisa, fotografe o "antes". Abra seu GitHub em aba anônima e veja com olhos de recrutador: foto visível? Username profissional? Bio com stack? Pinned repositórios com README? Anote os 3 piores problemas — eles viram as próximas tarefas.

  • Tire um screenshot do seu perfil GitHub atual (vá em modo anônimo para ver o que o recrutador vê).
  • Liste: foto, username, bio, nº de pinned, READMEs visíveis.
  • Anote 3 problemas prioritários para resolver nesta aula.
  • Faça o mesmo com seu LinkedIn: tire screenshot e liste 3 problemas.

Identidade & Profile README

~15 min GitHub

Atualize foto, nome completo, username e bio. Em paralelo, crie o repositório especial username/username e rode o Prompt 02 para gerar seu Profile README. Cole o resultado, revise 30% e faça commit.

  • Settings → Profile → trocar foto (rosto nítido, fundo neutro).
  • Atualizar Name (nome completo) e Bio (stack + foco + contato).
  • Criar repositório seu-username/seu-username (público, com README inicial).
  • Rodar Prompt 02, preencher dados, copiar resposta.
  • Editar o README.md do repositório, colar, revisar 30%, commit.
  • Recarregar seu perfil e confirmar que o README apareceu no topo.

Fixar os 6 repositórios certos

~10 min GitHub

Vá em Customize your pins e escolha 6 projetos completos — preferencialmente com README e deploy. Se não tem 6 bons, escolha os 3 melhores e marque esta etapa como "parcial": o resto da oficina vai justamente gerar o 4º.

  • No seu perfil, clique em Customize your pins.
  • Selecione até 6 repositórios. Priorize os com README e com deploy.
  • Remova "exercício-aula", "teste", "hello-world" — sinalizam imaturidade.
  • Salve. Recarregue e veja se a vitrine está coerente.

README profissional de 1 projeto

~15 min IA

Escolha 1 repositório fixado (de preferência o seu melhor). Rode o Prompt 01 preenchendo os dados dele. Cole no README.md da raiz, ajuste os exemplos de comando, adicione badges e faça commit.

  • Abra o repositório do projeto → editar README.md.
  • Copiar Prompt 01, preencher dados, rodar no ChatGPT/Claude.
  • Colar resposta no README. Revisar 30%: trocar clichês, ajustar nomes de comando.
  • Adicionar badges Shields.io para a stack real do projeto.
  • Commit com mensagem docs: improve README.

Deploy público do projeto

~15 min Deploy

Suba o mesmo projeto da etapa 4 em uma das plataformas do Bloco 3A. Se for React/Next → Vercel. Se for estático → GitHub Pages. Volte ao README e cole o link de deploy na seção correspondente.

  • Decidir plataforma pela stack (ver comparativo).
  • Criar conta (Vercel/Netlify/Render) com login do GitHub.
  • Conectar repositório → Deploy.
  • Copiar URL pública gerada.
  • Voltar no README do projeto e colar o link na seção "Deploy".
  • Commit: docs: add live deploy link.

Headline + Sobre no LinkedIn

~15 min IA

Rode os Prompts 03 e 04 com seus dados. Escolha a melhor headline entre as 10 variações. Cole o "Sobre" no LinkedIn, ajuste a voz e salve. Esse passo sozinho já multiplica suas chances de ser encontrado em buscas.

  • Rodar Prompt 03 com seus dados → escolher 1 headline entre as 10.
  • Atualizar headline no LinkedIn (perfil → editar → headline).
  • Rodar Prompt 04 → revisar 30% com sua voz.
  • Colar na seção "Sobre" do LinkedIn e salvar.

Rascunho do 1º post (de 5)

~10 min Conteúdo

Do framework "1 projeto = 5 posts" da Parte 1, rascunhe o Post 1 — O Anúncio. Estrutura: problema que existia → solução que você construiu → link do GitHub + deploy. Salve como rascunho no LinkedIn. Publicar fica para depois — o importante é ter o esqueleto pronto.

  • Em 3 linhas: qual problema motivou o projeto?
  • Em 3 linhas: qual solução você construiu?
  • Citar stack principal e 1 diferencial (a11y, performance, offline...).
  • Adicionar 2 links: GitHub do projeto + deploy ao vivo.
  • Salvar como rascunho no LinkedIn. (Publicar pode ser na próxima segunda.)

Progresso da Oficina

0 / 7 etapas concluídas

Clique no número de cada etapa (1, 2, 3...) para marcar como concluída.

Conclusão da Oficina

Seu perfil saiu do invisível.

Você saiu com: Profile README no GitHub, README profissional de um projeto, deploy público, headline e "Sobre" do LinkedIn reescritos e o rascunho do 1º post da série. Repita esse ciclo a cada novo projeto — em 3 meses, você tem uma marca técnica reconhecível.
